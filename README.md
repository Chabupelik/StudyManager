# 📚 StudyManager — Умная платформа управления учебным процессом

**StudyManager** — это модульная клиент-серверная платформа для комплексного управления учебными группами, расписанием, посещаемостью и дежурствами с омниканальной интеграцией (Telegram Mini App, ВКонтакте, Web SPA) и синхронизацией в реальном времени.

Платформа построена на принципах **чистой многослойной архитектуры (Clean Architecture)**: строгое разделение на слой контроллеров (API), бизнес-логики (Services), доступа к данным (Repositories) и валидации (Pydantic v2).

---

## 🎯 1. Ключевые возможности

### 👥 Мультигрупповая система и ролевая модель (RBAC)
- **Иерархия ролей:** `superadmin`, `curator` (куратор), `headman` (староста), `deputy` (зам. старосты), `student` (студент).
- **Многогрупповое членство:** пользователи могут состоять в нескольких учебных группах с независимыми ролями в каждой.
- **Инвайт-коды:** генерация одноразовых и многоразовых приглашений для быстрого присоединения студентов к группе.

### 📅 Конструктор расписания и оверрайды
- **Единый стандарт дней недели:** сквозная индексация `0 — Пн … 6 — Вс` (соответствие Python `.weekday()`, массивам фронтенда и структуре БД).
- **Семестровые интервалы:** поддержка интервалов действия пар (`valid_from`, `valid_until`) без затирания исторической сетки.
- **Оверрайды «на лету»:** отмены, переносы, назначения замен преподавателей и аудиторий без разрушения базового расписания.
- **WebSockets Live Sync:** мгновенная рассылка изменений расписания всем подключенным клиентам без перезагрузки интерфейса.

### 📊 Учёт посещаемости и аналитика
- **Посещаемость по парам:** фиксация статусов присутствия студентов (присутствовал, уважительная, болезнь, неуважительная).
- **Аналитический движок:** автоматический подсчёт академических часов, статистика посещаемости по предметам и студентам.
- **Экспорт в Excel:** генерация детализированных ведомостей и табелей посещаемости через Telegram-бота.

### 🧹 Умные дежурства (Duty Service)
- Автоматическое распределение дежурств по кабинетам с учётом очередей, истории дежурств и исключений.

### 🌉 Омниканальная коммуникация (Message Bridge)
- **VK ↔ Telegram Bridge:** автоматическая двусторонняя синхронизация сообщений между беседой группы ВКонтакте и Telegram-чатом.

## 🏗 2. Архитектура системы

```
┌────────────────────────────────────────────────────────┐
│                   Клиентский уровень                   │
│   Vue 3 SPA (Vite/Pinia)  │  Telegram Mini App  │  VK   │
└───────────────────────────┼────────────────────────────┘
                            │ HTTPS / WSS
┌───────────────────────────▼────────────────────────────┐
│                    FastAPI Backend                     │
│  ┌──────────────────────────────────────────────────┐  │
│  │ API Routers (/api/v1/*) — валидация Pydantic v2 │  │
│  ├──────────────────────────────────────────────────┤  │
│  │ Domain Services — бизнес-правила, транзакции, WS │  │
│  ├──────────────────────────────────────────────────┤  │
│  │ Repositories — SQLAlchemy 2.0 Async запросы      │  │
│  └──────────────────────────────────────────────────┘  │
└─────────────┬───────────────────────────┬──────────────┘
              │                           │
┌─────────────▼─────────────┐   ┌─────────▼──────────────┐
│       PostgreSQL 16       │   │        Redis 7         │
│  Транзакционное хранилище │   │  Кэш прав, блокировки  │
└───────────────────────────┘   └────────────────────────┘
              ▲
              │ asyncpg pool
┌─────────────┴─────────────┐
│    Aiogram 3 Bot Worker   │
│  Telegram бот + отчёты    │
└───────────────────────────┘
```

### Слои приложения (`app/`)
- **`app/api/v1/`**: тонкие контроллеры, проверка авторизации через зависимости (`CurrentUser`), строгая валидация схем запросов и ответов.
- **`app/services/`**: изоляция предметной логики, проверка прав на уровне группы, управление транзакциями (`session.commit()`), аудит-логи и WebSockets-уведомления.
- **`app/repositories/`**: абстракция доступа к данным через SQLAlchemy 2.0 AsyncSession. Репозитории не вызывают commit, обеспечивая чистоту транзакционных границ.
- **`app/models/`**: декларативные модели SQLAlchemy (`Mapped`, `mapped_column`).
- **`app/schemas/`**: Pydantic v2 схемы с валидацией форматов времени, дат и ролей.

## 🛡 4. Безопасность и аутентификация

1. **Криптографическая авторизация без паролей:**
   - **Telegram Mini App:** валидация подписи `initData` алгоритмом `HMAC-SHA256` с использованием секретного ключа бота и проверкой времени жизни данных (`auth_date`).
   - **VK Mini App:** валидация подписи `x-vk-sign` с использованием защищенного ключа приложения (`VK_PROTECTED_KEY`).
   - **Межсервисное взаимодействие:** заголовок `X-Internal-Secret` для защищенной связи фонового Telegram-бота с FastAPI бэкендом.
2. **Кэширование прав доступа:**
   - Права пользователя и роли в группах кэшируются в Redis для минимизации нагрузки на PostgreSQL.
   - При любых изменениях состава группы, ролей или удалении участников кэш инвалидируется автоматически.
3. **Журнал действий (Audit Trail):**
   - Все значимые операции (изменение расписания, оверрайды, смена ролей, удаление) логируются в таблицу `action_logs` с фиксацией автора, действия и времени (МСК).

## ⚙️ 5. Установка и запуск

### Предварительные требования
- Docker & Docker Compose
- Node.js 18+ (для локальной разработки фронтенда)
- Python 3.12+ (для локальной разработки бэкенда)

### Переменные окружения (`.env`)
Создайте файл `.env` в корневой директории на основе `.env.example`:
```env
# ===========================
# PostgreSQL
# ===========================
POSTGRES_USER=studymanager
POSTGRES_PASSWORD=your_secure_password
POSTGRES_DB=studymanager_db
POSTGRES_HOST=db
POSTGRES_PORT=5432

# ===========================
# Redis
# ===========================
REDIS_HOST=redis
REDIS_PORT=6379
REDIS_DB=0

# ===========================
# Telegram Bot
# ===========================
BOT_TOKEN=1234567890:ABCDEF...
GROUP_ID=-1001234567890
DEVELOPER_ID=your_telegram_id
ADMIN_IDS=123456789,987654321

# ===========================
# Внутренний секрет (Bot <-> Backend)
# ===========================
INTERNAL_SECRET=your_random_64char_hex_secret

# ===========================
# VK Integration (опционально)
# ===========================
VK_GROUP_ID=123456789
VK_CHAT_PEER_ID=2000000001
VK_TOKEN=vk1.a.your_vk_token
VK_PROTECTED_KEY=your_vk_protected_key

# ===========================
# Настройки приложения
# ===========================
SHOW_DOCS=false
```

### Запуск через Docker Compose (Production)
```bash
# Сборка и запуск всех сервисов (db, redis, backend, bot)
docker compose up -d --build

# Применение миграций базы данных
docker compose exec backend alembic upgrade head
```

### Локальная разработка (Local Dev)

**1. Инфраструктура:**
```bash
docker compose up -d db redis
```

**2. Бэкенд:**
```bash
python -m venv venv
# Windows:
venv\Scripts\activate
# Linux/macOS:
source venv/bin/activate

pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:create_app --reload --port 8000
```

**3. Фронтенд:**
```bash
cd frontend
npm install
npm run dev
```

**4. Проверка качества кода:**
```bash
# Линтинг и форматирование бэкенда
python -m ruff check .
python -m ruff format --check .

# Статическая типизация
python -m mypy app tgbot --ignore-missing-imports

# Сборка фронтенда
cd frontend && npm run build
```

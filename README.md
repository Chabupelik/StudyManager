# 📚 StudyManager — Умная платформа управления учебным процессом

**StudyManager** — это современная модульная платформа для комплексного управления учебными группами, расписанием, посещаемостью и дежурствами с омниканальной интеграцией (Telegram, ВКонтакте, Web SPA) и синхронизацией в реальном времени.

Платформа построена на принципах **чистой многослойной архитектуры (Clean Architecture)**: разделение на слой контроллеров (API), бизнес-логики (Services), доступа к данным (Repositories) и валидации (Pydantic v2).

---

## 🎯 1. Ключевые возможности

### 👥 Мультигрупповая система и ролевая модель (RBAC)
- **Иерархия ролей:** `superadmin`, `curator` (куратор), `headman` (староста), `deputy` (зам. старосты), `student` (студент).
- **Многогрупповое членство:** пользователи могут состоять в нескольких учебных группах с независимыми ролями в каждой.
- **Инвайт-коды:** генерация приглашений и быстрое присоединение студентов к группе.
- **Кэширование прав в Redis:** оптимизированное получение прав с распределёнными блокировками и инвалидацией при изменениях.

### 📅 Конструктор расписания и оверрайды
- **ISO-стандарт дней недели:** унифицированная индексация `1 — Пн … 7 — Вс` на всех уровнях (БД, API, фронтенд, боты).
- **Семестровые интервалы:** поддержка интервалов действия пар (`valid_from`, `valid_until`) без затирания истории.
- **Оверрайды «на лету»:** отмены, переносы, назначения замен преподавателей и аудиторий без разрушения базовой сетки.
- **WebSockets Live Sync:** мгновенная рассылка изменений расписания всем подключенным клиентам без перезагрузки страницы.

### 📊 Учёт посещаемости и статистика
- **Посещаемость по парам:** фиксация присутствия/отсутствия студентов (уважительная, болезнь, неуважительная).
- **Аналитический движок:** автоматический подсчёт академических часов, статистика посещаемости по предметам и студентам.
- **Экспорт в Excel:** генерация детализированных ведомостей и табелей посещаемости через Telegram-бота.

### 🧹 Умные дежурства (Duty Service)
- Автоматическое распределение дежурств по кабинетам/доске с учётом очередей, истории и чёрного списка студентов.

### 🌉 Омниканальная коммуникация (Message Bridge)
- **VK ↔ Telegram Bridge:** автоматическая двусторонняя синхронизация сообщений между чатом группы ВКонтакте и Telegram-каналом/чатом.

## 🏗 2. Архитектура системы

```
┌────────────────────────────────────────────────────────┐
│                   Клиентский уровень                   │
│   Vue 3 SPA (Vite/Pinia)  │  Telegram Mini App  │  VK   │
└───────────────────────────┼────────────────────────────┘
                            │ HTTPS / WSS
┌───────────────────────────▼────────────────────────────┐
│                    FastAPI Backend                     │
│  ┌──────────────────────────────────────────────────┐  │
│  │ API Routers (/api/v1/*) — валидация Pydantic v2 │  │
│  ├──────────────────────────────────────────────────┤  │
│  │ Domain Services — бизнес-правила, транзакции, WS │  │
│  ├──────────────────────────────────────────────────┤  │
│  │ Repositories — SQLAlchemy 2.0 Async запросы      │  │
│  └──────────────────────────────────────────────────┘  │
└─────────────┬───────────────────────────┬──────────────┘
              │                           │
┌─────────────▼─────────────┐   ┌─────────▼──────────────┐
│       PostgreSQL 16       │   │        Redis 7         │
│  Транзакционное хранилище │   │ Кэш прав, блокировки   │
└───────────────────────────┘   └────────────────────────┘
              ▲
              │ asyncpg pool
┌─────────────┴─────────────┐
│    Aiogram 3 Bot Worker   │
│  Telegram бот + отчёты    │
└───────────────────────────┘
```

### Слои приложения (`app/`)
- **`app/api/v1/`**: тонкие контроллеры, проверка авторизации через зависимости (`CurrentUser`), приём строго типизированных схем запросов и ответов.
- **`app/services/`**: изоляция предметной логики, проверка прав на уровне группы, управление транзакциями (`session.commit()`), аудит-логи и WebSockets-уведомления.
- **`app/repositories/`**: абстракция доступа к данным через SQLAlchemy 2.0 AsyncSession. Репозитории не вызывают commit, обеспечивая чистоту транзакционных границ.
- **`app/models/`**: декларативные модели SQLAlchemy (`Mapped`, `mapped_column`).
- **`app/schemas/`**: Pydantic v2 схемы с валидацией форматов времени, дат и ролей.

## 💻 3. Стек технологий

- **Backend:** Python 3.12, FastAPI, SQLAlchemy 2.0 (Async), Asyncpg, Pydantic v2, ZoneInfo (`Europe/Moscow`).
- **Базы данных и кэш:** PostgreSQL 16, Redis 7, Alembic (миграции схемы).
- **Web Frontend:** Vue 3, Vite, Pinia, Vue Router, Tailwind CSS, Lucide Icons.
- **Боты и интеграции:** Aiogram 3, OpenPyXL, VK API, Google Gemini GenAI.
- **Инфраструктура & QA:** Docker, Docker Compose, Nginx, Ruff, Mypy.

---

## 🛡 4. Безопасность и аутентификация

1. **Мультиплатформенная авторизация:**
   - Валидация подписи `initData` Telegram Mini App (`HMAC-SHA256`).
   - Авторизация через VK Mini App / VK Silent Token.
   - JWT Access + Refresh токены с ротацией.
2. **Кэширование прав:**
   - Права пользователя и роли в группах кэшируются в Redis.
   - При изменениях состава группы, ролей или удалении участников кэш инвалидируется автоматически.
3. **Журнал действий (Audit Trail):**
   - Все значимые операции (изменение расписания, оверрайды, смена ролей, удаление) логируются в таблицу `action_logs` с фиксацией автора, действия и времени (МСК).

## ⚙️ 5. Установка и запуск

### Предварительные требования
- Docker & Docker Compose
- Node.js 18+ (для локальной разработки фронтенда)
- Python 3.12+ (для локальной разработки бэкенда)

### Переменные окружения (`.env`)
Создайте файл `.env` в корневой директории:
```env
POSTGRES_USER=studymanager
POSTGRES_PASSWORD=your_secure_password
POSTGRES_DB=studymanager_db
POSTGRES_PORT=5432

REDIS_HOST=redis
REDIS_PORT=6379

BOT_TOKEN=your_telegram_bot_token
DEVELOPER_ID=your_telegram_id
BACKEND_URL=http://backend:8000

SECRET_KEY=your_jwt_secret_key
ACCESS_TOKEN_EXPIRE_MINUTES=1440
```

### Запуск через Docker Compose (Production / Full Dev)
```bash
# Сборка и запуск всех сервисов (db, redis, backend, bot)
docker-compose up -d --build

# Применение миграций базы данных
docker-compose exec backend alembic upgrade head
```

### Локальная разработка (Local Dev)

**1. Инфраструктура:**
```bash
docker-compose up -d db redis
```

**2. Бэкенд:**
```bash
python -m venv venv
# Windows:
venv\Scripts\activate
# Linux/macOS:
source venv/bin/activate

pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:create_app --reload --port 8000
```

**3. Фронтенд:**
```bash
cd frontend
npm install
npm run dev
```

**4. Проверка качества кода:**
```bash
# Линтинг и форматирование бэкенда
python -m ruff check .
python -m ruff format --check .

# Статическая типизация
python -m mypy app tgbot --ignore-missing-imports

# Сборка фронтенда
cd frontend && npm run build
```
